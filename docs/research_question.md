RQ1 — Effectiveness of reasoning: Do reasoning-enabled LLMs out-perform non-reasoning baselines on log parsing, log analysis, vulnerability detection, technical debt detection, and code generation?
RQ2 — Agentic moderation: How do multi-agent setups (planner–executor, proposer–reviewer) compare to single-agent execution in accuracy and robustness under matched toolchains and budgets, and do these effects differ between reasoning and non-reasoning models?
RQ3 — Explanation prompting: How do prompting styles (no-explanation, explain-after, explain-before, evidence-bound) impact explanation usefulness and faithfulness (evaluating explanation quality using four metrics, completeness, informativeness, clarity, and actionability), and do these effects differ between reasoning and non-reasoning models?
RQ4 — Cost and efficiency: What latency/token overheads accompany reasoning, agentic orchestration, and explanation prompting, and what are the resulting quality–cost trade-offs?

Study Design. In this paper, we conduct and report a controlled empirical study across five representative software engineering tasks: log parsing, log analysis, vulnerability detection, technical debt detection, and code generation. The study is organized as a phased, factor-separated evaluation that centers explicit reasoning while treating agentic orchestration and explanation prompting as controlled moderators.

Phase I estimates the main effect of reasoning by comparing a representative reasoning-enabled model against a matched non-reasoning baseline under a single-agent, answer-only condition. Both models operate with identical toolchains, time budgets, temperatures, and stop criteria. This phase runs across four task families—log parsing, log analysis, vulnerability detection, and code generation—so that the reasoning estimate is not confounded by task idiosyncrasies. Instances are stratified by difficulty and randomized in presentation order; each condition is executed in independent, cache-free runs with fixed seeds and repeated trials to quantify stochastic variance.

Phase II examines how collaboration moderates the reasoning effect by introducing two agentic patterns under the same budgets and tools: a planner–executor workflow that decomposes tasks into sub-steps with controlled tool use (tests, static analyzers, log filters), and a proposer–reviewer workflow that adds a single critique–revise round focused on correctness and risk (e.g., regression, security). To keep comparisons interpretable, Phase II narrows to two representative tasks where tools materially affect outcomes — log analysis and code generation—using the same two models from Phase I. This design tests whether gains attributed to “reasoning” are in fact amplified (or substituted) by orchestration.

Phase III investigates explanation prompting as a moderator of both task outcomes and explanation quality. The same two tasks and two models are evaluated under four prompting regimes: no-explanation (answer only), explain-after (post-hoc rationale), explain-before (concise plan-then-answer), and evidence-bound (answer plus machine-parsable citations to code spans, tests and outcomes, log queries, or static-analysis rule IDs; unsupported claims marked explicitly). Explanations are scored on two orthogonal axes. Usefulness is assessed by blinded raters using a developer-oriented rubric that captures clarity, localization to concrete artifacts, actionability, testability/reproducibility, and fit to context. Faithfulness is computed from task-grounded evidence: overlap between cited and labeled spans, execution alignment of cited tests or log filters, contradiction rate when claims are falsified by execution, and edit–claim consistency for code changes. Throughout all phases, efficiency is recorded as latency and token usage, enabling quality–cost analyses.

Across phases, the evaluation harness enforces environment parity and reproducibility: fresh containers per run; identical compilers, linters, analyzers, and test runners; fixed timeouts; and standardized logging of prompts, transcripts, patches, tool outputs, and explanations. Sampling plans target sufficient power for medium effects, with pilot variance used to size final runs; analyses use mixed-effects models with condition as a fixed effect and task instance and rater (for usefulness) as random effects, and employ multiplicity control (Holm–Bonferroni) for familywise error. To support external auditing and reuse, the study releases a replication package containing task corpora with ground-truth spans and tests, prompt templates, configuration files, execution scripts, scoring code, and anonymized rater sheets. This design yields clean estimates of the contribution of explicit reasoning, quantifies how lightweight agentic patterns and evidence-bound prompting modulate outcomes, and reports the associated efficiency trade-offs in conditions that reflect real SE practice.
